Foundation · Layout

Layout

A mobile-first grid of 4, 8 and 12 columns whose gutters and margins grow at 768px and 1024px, a 1280px container and six page templates.

Overview

The Debate App is mobile first. Base styles target a 360px phone; two breakpoints (768px and 1024px) add columns, wider gutters and wider margins by changing three tokens, so components rarely need their own media queries. Content is centred in a 1280px container.

  • Lay pages out on .container + .grid; the grid reads --layout-columns, --layout-gutter and --layout-margin.
  • Use min-width queries in rem only.
  • No page scrolls sideways at 320px.

Breakpoints

TokenMin widthTypical deviceWhat changes
(base)0Phones, 360px design width4 columns; dialogs are bottom sheets; the editor toolbar wraps

--layout-breakpoint-md768px · 48remTablets8 columns, 24px gutter, 32px margin; meeting rows show the full excerpt
--layout-breakpoint-lg1024px · 64remLaptops12 columns, 32px gutter, 48px margin; .span-4/5/7/8 split; .sticky-aside sticks
--layout-breakpoint-xl1280px · 80remDesktopsContainer reaches its maximum and centres
--layout-breakpoint-2xl1536px · 96remWide screensNothing new; margins grow around the container

Custom properties cannot be read inside @media, so the breakpoint tokens are documentation and JavaScript values; CSS repeats the rem number by convention (@media (min-width: 48rem)).

  • .grid is repeat(var(--layout-columns), minmax(0, 1fr)) with gap: var(--layout-gutter).
  • .span-4, .span-5, .span-7, .span-8 are full width until 1024px, then take that many of 12 columns. Use 8 + 4 for a main column with an aside, 7 + 5 for two related columns.
  • .grid--auto fills cards at a minimum of 18rem each (card galleries).

Container and measure

  • .container is full width, capped at --layout-container-max (1280px), centred, with --layout-margin on both sides.
  • Prose stops at --layout-measure (65ch); every <p> has it as a max-width.
  • The auth card is 26rem wide and centred in the viewport (.auth-layout, .auth-card); a dialog panel is 32rem.

Top bar

The Debate App
MeetingsNew meeting
Top bar: brand, primary links, spacer, account avatar. The same bar is used on every signed-in page.
  • The top bar is 56px (--layout-topbar-height), sticky, and the page sets scroll-padding-top to its height plus 16px so focused and linked content is never hidden under it.
  • The Debate App has no bottom tab bar; the primary links stay in the top bar at every width. --layout-tabbar-height remains in the token set for the shared stylesheet.
  • --layout-sidebar-width (256px) is used by this documentation site's navigation only; the Debate App itself has no sidebar.

Usage

  • Put spans on grid children with the .span-* classes; never write style="grid-column: span 8" plus a max-width override.
  • A page has one .container; full-bleed elements (top bar, banners) sit outside it.
  • Use 100dvh, not 100vh, for full-height layouts so mobile browser bars do not clip content.
  • Never hide content at a breakpoint that is not reachable another way; the two primary links stay in the top bar at every width.

Accessibility

  • Reflow (1.4.10): every page works at 320px CSS width with no sideways scroll; only data tables scroll, inside .table-wrap.
  • Focus not obscured (2.4.11): the sticky top bar, the save bar and toasts never cover the focused element.
  • Order (2.4.3): visual order equals DOM order at every width; asides come after the main column in the source.
  • Landmarks: one header, nav (labelled "Primary"), main per page.
