Prose

Typography for the HTML that organisers write in the editor and readers see on the meeting page.

WCAG 2.2 AAStatus: stableClass only

Overview

Prose styles the HTML that the rich-text editor produces: paragraphs, two heading levels, lists and code blocks. It is a class, not a component with parts: apply .prose to the container of stored rich text. The same class sits on the editor's content region so writing and reading look identical.

  • Use it for Abstract, Agenda and Minutes on the meeting page, inside a card.
  • Do not use it for UI chrome such as form labels or buttons; those have their own text styles.

Anatomy

Prose has no fixed parts, only elements it styles:

  • p is limited to --layout-measure (65ch).
  • h2 uses --text-h3 and h3 uses --text-h4; both open a section with extra space above.
  • ul, ol and li are indented by --space-5.
  • pre is mono, small, on a sunken surface.
  • Each block is separated from the previous one by --space-3.

Sizes

One size. Body copy uses the base font size and --line-height-relaxed inside the editor. The measure is capped at --layout-measure.

States

Prose is static text with no interactive states. Whether it can be edited is the container's job.

Responsive behaviour

  • Text reflows to its container; paragraphs stop at 65ch on wide screens and fill the column on phones.
  • pre scrolls sideways inside its own box; the page does not.
  • No size changes at breakpoints.

Theming

Prose sets no colours of its own except the code block's --color-bg-surface-sunken; text inherits --color-fg-default. It works on any surface that already meets contrast, in both themes.

Accessibility

Role and pattern

No role and no ARIA pattern: semantic HTML only. Headings inside prose continue the page outline (h2 and h3 below the page h1), and lists stay real lists.

Keyboard

Nothing in prose is focusable except links the author adds. A pre that scrolls should get tabindex="0" and a label so keyboard users can reach it.

Focus

Links inside prose use the shared focus ring.

Labelling

Images inserted by the editor need alt text; a purely decorative image gets alt="".

Content

  • Headings are short nouns ("Highlights", "Actions"); do not skip levels.
  • Use real lists for agenda items and actions, one item per line.
  • Code blocks are for literal text only.
  • Keep paragraphs short enough to scan during a meeting.
