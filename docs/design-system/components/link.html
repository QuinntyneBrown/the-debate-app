Link

Links take people somewhere: to the agenda, back to sign in, to the field that needs fixing. They are plain, underlined anchors with no class.

WCAG 2.2 AAStatus: stableNative <a href>

Overview

A link goes to another page or another place on the page. If activating it changes data (saves, signs out, deletes, renews a session), use a button instead. Links are styled by the bare a selector, so any anchor in running text looks right with no class.

  • Inline links sit inside a sentence: "End must be after start: fix the end time."
  • Standalone links stand on their own line or in an alert's actions: "Open the agenda", "Enter a name".

Visited links are not styled separately. The Debate App is a small tool a club revisits every week; a visited colour would turn most links on the meetings list a different colour for no useful reason. :visited keeps the default link colour.

Links with their own look have their own pages: the meeting titles in meeting row, the top bar nav links in top bar and navigation, menu items in menu, and anchors given .btn in button.

Anatomy

  1. TextSays where the link goes; it is the accessible name. --color-fg-link, inherits the surrounding font.
  2. UnderlineAlways on. --border-width-hairline thick, offset 0.15em; thickens to --border-width-thick on hover.

Variants

Both variants use the same styles; they differ only in where they sit and how much the text has to carry.

Links inside alerts and the error summary take the alert's colour (.alert__actions a inherits); see form layout.

Sizes

Links take the size of the text around them; there is no size modifier.

States

Hover and focus are forced with data-state; real pages get them from :hover and :focus-visible. Visited and active look the same as default on purpose. Links are never disabled: if a destination is not available, do not render the link.

Responsive behaviour

  • Links wrap with their text and never truncate. Long meeting names in links wrap onto a second line.
  • Error-summary links sit in the alert and wrap with it at every width.
  • Keep link text short enough that a row of them never forces horizontal scroll at 360px.

Theming

Links read two semantic tokens: --color-fg-link and --color-fg-link-hover. In light they are deep violets on a pale page; in dark they switch to --palette-violet-300 so they stay readable on the dark surfaces. Underline thickness comes from the border-width tokens, so a theme never needs to touch it.

a { color: var(--color-fg-link); text-decoration-thickness: var(--border-width-hairline); }
a:hover { color: var(--color-fg-link-hover); text-decoration-thickness: var(--border-width-thick); }

Accessibility

Role and pattern

Native <a href> (the WAI-ARIA APG Link pattern is satisfied by the native element). Never an <a> without href, never a <span> with a click handler.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the link.
EnterFollows the link. Space scrolls the page, as with every native link.

Focus

The shared focus ring (--color-focus-ring, offset --focus-ring-offset) on :focus-visible. Error-summary links move focus to their field because each href is the field's #id.

Labelling

The link text is the accessible name and must make sense alone (WCAG 2.4.4). Repeated short links add hidden context: "Open Universal basic income" reads as "Open Universal basic income". Never "click here".

The underline is always present, so a link never relies on colour alone (WCAG 1.4.1).

Motion

None. Hover changes colour and underline thickness instantly.

Touch

Inline links are exempt from the 24px target rule (WCAG 2.5.8 inline exception). Standalone links sit alone on a line of body text, so their line box and spacing give at least a 24px target; nothing else is tappable within 24px of them.

Content

  • Say where the link goes or what it fixes: "Open the agenda", "Enter a name", "End must be after start".
  • Sentence case; no trailing full stop inside the link text.
  • Link the words that describe the destination, not the whole sentence: "Check the password."
  • Error-summary links name the problem, not the field: "Enter a name", "Check the password".
