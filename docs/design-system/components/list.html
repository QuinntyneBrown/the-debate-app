List

A list stacks rows that share one shape: a date, a title, a short meta line and at most two actions. It is how Jordan Reyes scans the club's meetings, upcoming first, then past.

Overview

Use a list when each row is one thing with a name and a line of context, and the reader scans down to pick one. The Debate App has one list today: the meeting list, split into Upcoming and Past, each its own list under an overline heading. The row itself is documented in meeting row; this page covers the container.

  • Meetings: ul.list.card.card--flush of li.meeting rows with Edit and Delete icon buttons.
  • Identity pair: .list__title and .list__meta alone, as the name and @admin handle at the top of the account menu.

A list sits flush inside a card (.card.card--flush) so the row dividers run edge to edge. Meetings are not compared across columns, so there is no table. See lists and tables.

Anatomy

  1. Containerul.list inside .card.card--flush: no bullets, no spacing, rows stacked with a hairline divider except after the last.
  2. Title.meeting__title holds the stretched link to the meeting; the generic .list__title uses --text-label.
  3. MetaWhen and one excerpt line; the generic .list__meta uses --text-body-sm in --color-fg-muted.
  4. Trailing actionsAt most two icon-only buttons, each named after its row.

Variants

There is one list. What changes is what the rows are; the meeting list is the only place it holds full rows.

Sizes

One size. A meeting row is a 3.5rem date chip plus padding, well above the 44px touch target. Do not shrink the padding to fit more rows; a long list scrolls.

States

The list container is not interactive. Hover and focus belong to the row (see meeting row) and the buttons inside it (see button). The list's own states are about its content.

  • Loading shows two skeleton rows of the same shape per section, aria-hidden on the rows and aria-busy="true" with an aria-label of "Loading meetings" on the container (see skeleton).
  • Empty replaces the whole list with an empty state that says why and offers New meeting.
  • Long lists (19 meetings back to May) stay one list per section. The API returns every meeting in one call, so there is no paging.

Responsive behaviour

  • A row keeps its date chip and actions at every width. .meeting__body has min-width: 0, so a long title wraps instead of pushing the actions off screen.
  • The excerpt stays on one line with an ellipsis; the full text is in its title attribute.
  • Trailing actions are icon-only so two of them fit beside the body at 360px.

Theming

The list reads --color-border-default for dividers, --color-fg-default for titles and --color-fg-muted for meta. It has no background of its own, so it takes the card's surface in both themes. The date chip swaps between the accent tint (upcoming) and a muted tint (past).

Accessibility

Role and pattern

A native <ul> of <li>, so screen readers announce "list, 3 items". No ARIA role. Loading placeholders are aria-hidden inside an aria-busy container, so nothing is announced until the real rows arrive.

Keyboard

KeyAction
Tab / Shift+TabMoves between the title link and the actions in each row, in reading order. Rows themselves are not focus stops.
Enter / SpaceActivates the focused link or button.

Focus

The title link takes focus and the whole row shows the focus ring (:focus-within on the row). A row never gets tabindex.

Labelling

Wrap each list in a <section aria-labelledby> pointing at its overline heading ("Upcoming", "Past"). Icon-only buttons name their row: "Edit Universal basic income", never just "Edit". The date chip is aria-hidden because the "When" line says the same in words.

Row dividers use --color-border-default; they are decorative grouping, so 1.4.11 does not apply.

Motion

None. Skeleton rows shimmer on --duration-loop and stop under prefers-reduced-motion.

Touch

Icon buttons are 32px with 12px between neighbours inside a row of at least 56px, so a thumb cannot hit the wrong row.

Content

  • Title first, the meeting's real name: "Universal basic income", "Four-day work week".
  • Meta is the day and time ("Tue 13 Oct · 7:00 pm–8:30 pm"), then one excerpt line from the abstract.
  • Relative day only for tomorrow ("Tomorrow · 7:00 pm–8:30 pm"); short dates after that.
  • Upcoming first, soonest at the top; past after it, newest at the top.

Class / attributeEffect
.listOn a <ul> or <ol>: removes bullets and spacing, stacks rows.
.meetingOne meeting row; divider except on the last row. See meeting row.
.list__title / .list__metaName and one line of context outside a meeting row.
