Meeting row

One row per meeting on the Meetings page. The whole row opens the meeting; Edit and Delete sit on top of it and appear when you hover or focus the row.

Overview

Use a meeting row inside a list card (.list.card.card--flush) wherever meetings are listed: Upcoming and Past on the Meetings page. Use a card for a single meeting on its own page, and a plain link for a mention inside text.

  • Date tile shows day and month at a glance and is hidden from assistive technology; the same date is in the "when" line.
  • Title link is the only link that opens the meeting. Its ::after is stretched over the whole row, so the full row is one large click target without nesting interactive content in a link.
  • When and excerpt give the time range and the first line of the abstract; the excerpt truncates to one line.
  • Actions (Edit, Delete) are ghost icon buttons raised above the stretched link. They show on hover and keyboard focus on wide screens and always on touch and narrow screens.
  • Past (.meeting--past) greys the date tile for meetings that have already happened.

Anatomy

  1. Date tile.meeting__date: day in --font-size-2xl bold, month as overline, --color-accent-subtle fill, aria-hidden="true".
  2. Title link.meeting__title a, --text-h4; its ::after covers the row (inset: 0).
  3. When.meeting__when: relative day or weekday and date, then start–end times, in --color-fg-muted.
  4. Excerpt.meeting__excerpt: one line, ellipsis on overflow.
  5. Actions.meeting__actions: --z-raised so they sit above the stretched link; each icon button names the meeting.

Variants

Two variants: upcoming (default) and past. Past only changes the date tile; the row stays fully interactive so minutes can still be edited.

Sizes

A meeting row has one size; its height follows its content. Action buttons are small (36px) and the date tile is at least 3.5rem wide.

States

Hover and focus are forced with data-state on the row (and on the title link for link hover); real pages use :hover, :focus-within and :has(a:focus-visible). On a wide pointer device the actions are transparent until the row is hovered or contains focus; the matrix shows both outcomes.

  • Hover: --color-bg-subtle background; the title turns --color-fg-accent; actions fade in over --duration-fast.
  • Focus: the title link takes focus; the row shows the shared ring inside its edge (offset by minus --focus-ring-width) so rows in a flush card do not clip it. Actions are revealed by :focus-within.
  • Loading: a skeleton row stands in; the row itself has no loading state. Disabled does not apply: a meeting is always openable.
  • Deleting: the Delete button opens a confirmation dialog; while the request runs it carries aria-busy="true" (see button).

Responsive behaviour

  • Under 48rem: two columns (date tile, body). Actions form a second line under the text, always visible, nudged left by --space-2 to align icon with text.
  • 48rem and up with hover: hover: three columns; actions are a right-hand column with opacity: 0 until the row is hovered or has focus inside.
  • 48rem and up with hover: none (tablets, touch laptops): three columns, actions always visible, since touch cannot hover.
  • The body has min-width: 0 so a long title wraps and a long excerpt truncates instead of widening the card (see the long mock).

Theming

The row reads semantic tokens only: --color-accent-subtle and --color-fg-accent for the upcoming tile, --color-bg-subtle and --color-fg-muted for the past tile, --color-bg-subtle for hover and --color-border-default for the divider. Dark mode swaps these through the theme tokens; nothing in the row is theme-specific.

/* A denser list reassigns spacing only; it never edits .meeting */
.compact .meeting { padding: var(--space-3); gap: var(--space-3); }

Accessibility

Role and pattern

A list item in a <ul> that has a heading before it (Upcoming, Past). The title is one native <a href>; the whole-row hit area is a pseudo-element on that link, so there is a single link per meeting and no nested interactive content. Edit is an <a> (it navigates), Delete is a <button type="button"> (it opens a dialog). The date tile is aria-hidden="true"; the same date is read from the "when" line.

Keyboard

KeyAction
Tab / Shift+TabMoves through title link, Edit, Delete for each row in DOM order. Focusing any of them reveals the actions.
Enter on the titleOpens the meeting.
Enter on EditOpens the edit page.
Enter, Space on DeleteOpens the Delete meeting dialog.

Hidden actions are only visually hidden (opacity: 0), never display: none, so they stay in the tab order and a keyboard user reaches them without a pointer. Where hover is unavailable (hover: none) they are always shown.

Focus

The ring is drawn on the row (:has(.meeting__title a:focus-visible)) in --color-focus-ring, inside the edge. The link's own outline is removed because the row ring replaces it. Edit and Delete use the standard button ring.

Labelling

The title is the link name. Each icon button names verb and meeting: "Edit Universal basic income", "Delete Universal basic income", so a list of buttons is unambiguous in a screen reader's links and buttons lists. Do not add a "Read more" link; the title is the link.

Motion

Background and action opacity transition over --duration-fast; the tokens zero it under prefers-reduced-motion. Nothing moves.

Touch

The whole row is the target (well over 44px). Action buttons are 36px with --space-1 between them; on touch they are always visible so nothing depends on hover.

Content

  • The title is the meeting name, as typed: "Should cities ban cars from downtown?". Never "Meeting 12".
  • When reads "Tomorrow · 7:00 pm–8:30 pm" within a week and "Tue 27 Oct · 7:00 pm–8:30 pm" beyond; times use a lowercase am/pm and an en dash.
  • The excerpt is the first sentence or two of the abstract as plain text, one line.
  • Action names are "Edit {meeting name}" and "Delete {meeting name}". Sentence case, no ellipsis.
