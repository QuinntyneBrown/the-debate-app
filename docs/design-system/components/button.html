Button

Buttons let a club admin do something: sign in, save a meeting, delete a meeting, discard changes. One primary button per view says what matters most.

Overview

Use a button when activating it changes something: it submits a form, opens a dialog, shows or hides a password or deletes a meeting. Use a link when it only takes the person somewhere. Use the menu for the account actions under the avatar.

  • Primary is the one action the view exists for: "New meeting", "Create meeting", "Save", "Sign in", "Keep editing". Never two per view.
  • Secondary (the default look) is for the other actions that still matter: "Cancel", "Back to meetings".
  • Ghost is the quiet way out or a row action: the "Meetings" back button, and the close, edit, delete and show/hide password icons.
  • Danger removes something. It appears on the meeting edit page, in the delete-meeting dialog ("Delete meeting") and in the discard-changes dialog ("Discard").

A .btn class on an <a href> is fine when the action is really navigation: "New meeting", "Edit" and "Back to meetings" open pages. The element stays a link; only the look changes. There is no link-style button.

Anatomy

  1. Leading icon (optional)1.25em square, 2px stroke, inherits the label colour, aria-hidden="true".
  2. LabelA short verb phrase in sentence case; it is the accessible name.
  3. ContainerHeight from --control-height-*, --radius-full corners (a pill), hairline border, padding from the spacing scale.

Variants

Variants change emphasis, not meaning. Pick by how much attention the action deserves on this view.

Primary, secondary, ghost, danger: highest to lowest emphasis, with danger kept for deleting or discarding.
HTML
<button class="btn btn--primary" type="button">Create meeting</button>
<button class="btn" type="button">Cancel</button>
<button class="btn btn--ghost" type="button">Meetings</button>
<button class="btn btn--danger" type="button">Delete meeting</button>

With icons, icon-only and block

Icon-only buttons carry an aria-label; the icon is aria-hidden. The eye is the show/hide password button; it sets aria-pressed and sits in a text field. Block buttons fill the sign-in card.
HTML
<button class="btn btn--ghost btn--icon" type="button" aria-label="Close">
  <svg class="icon" aria-hidden="true" viewBox="0 0 24 24">…</svg>
</button>
<button class="btn btn--primary btn--lg btn--block" type="submit">Sign in</button>

Sizes

Medium is the default ("New meeting", "Save", "Create meeting"). Small lives in list rows (the edit and delete icons) and the "Meetings" back button. Large is for the one action a whole screen leads to: "Sign in".

Small 36px, medium 44px, large 52px. Heights --control-height-sm/md/lg; padding --space-3/4/6; font --font-size-sm/md/lg.

States

Every variant has the same six states. Pointer and focus states are forced here with data-state so they can be reviewed without a mouse; real pages get them from :hover, :focus-visible, :active, disabled and aria-busy.

Both themes

  • Loading keeps the button's width, hides the label behind a spinner and ignores clicks. The delete-meeting mock sets aria-busy="true" on the pressed button and disabled on its neighbour ("Cancel") so nothing is sent twice. Because a disabled button drops focus, the page moves focus to the result when the request ends: the toast, the error summary or the next page.
  • Disabled uses the native attribute: not focusable, 50% opacity. It is used for a submit in flight and for nothing else.
  • Pressed: only the show/hide password button sets aria-pressed. The editor toolbar buttons are .editor__btn, not .btn.

Responsive behaviour

  • On the sign-in screen the primary is .btn--lg.btn--block at every width; the card itself is capped in width.
  • In the meeting form the Save or Create button sits in the page-header save bar (see form layout); in dialog footers buttons sit end-aligned on one row and wrap when the row is too narrow.
  • Under 640px dialogs become bottom sheets; their footer buttons keep the same order.
  • Every size is at least 36px tall and medium is 44px, so no button needs extra hit area on touch screens.
  • Labels never truncate (white-space: nowrap). A label that does not fit at 360px is too long; shorten the verb phrase.

Theming

The button reads semantic tokens through component tokens: --btn-bg, --btn-fg, --btn-border, --btn-bg-hover, --btn-bg-active, --btn-height, --btn-padding and --btn-font-size. Variants and sizes only reassign those; a context can do the same without touching .btn.

/* A context reassigns the component tokens; it never edits .btn */
.some-context .btn { --btn-height: var(--control-height-sm); --btn-font-size: var(--font-size-sm); }

In the dark theme the accent lightens to --palette-violet-300 and the primary label flips to --color-fg-on-accent (--palette-violet-950), so the label stays dark on a light button. Danger does the same with --palette-red-300.

Accessibility

Role and pattern

Native <button type="button">, or type="submit" inside a form. A link that looks like a button is still an <a href>. Never a <div> with a click handler. No ARIA role is needed.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the button in DOM order.
Enter, SpaceActivates the button. Space activates on key up, so a mis-press can be cancelled by moving away first.
Enter in a text fieldSubmits the form through its type="submit" button ("Sign in", "Save").

Focus

One shared ring (--focus-ring-width of --color-focus-ring, offset by --focus-ring-offset) on :focus-visible only, so taps and clicks do not show it. The offset gap shows the surface colour, which keeps the ring visible against the primary fill. In the delete-meeting dialog focus starts on "Cancel", and in the discard-changes dialog on "Keep editing", never on the danger button.

Labelling

The visible label is the accessible name. Icon-only buttons set aria-label with the verb and, where several share a view, the object: "Close", "Show password", "Edit Four-day work week", "Delete Four-day work week". The Debate App has no tooltips, so icon-only is reserved for icons whose meaning is plain from context. A loading button keeps its name.

Motion

Background, border and shadow transition over --duration-fast (120ms); the active state moves down 1px. The loading spinner turns once every --duration-loop/2 (700ms). Under prefers-reduced-motion the tokens zero the durations and loops stop after one pass.

Touch

Small 36px, medium 44px and large 52px all clear the 24px minimum; medium and large meet the 44px comfortable target. Small buttons sit at least --space-2 apart in rows.

Content

  • Labels are verb phrases in sentence case: "Save", "Create meeting", "New meeting", "Sign in". Never "OK", "Yes" or "Submit".
  • The tone is plain and calm; no exclamation marks.
  • Destructive labels name what is lost ("Delete meeting"), and the safe choice names what is kept ("Cancel", "Keep editing").
  • Keep labels to about three words; the longest in the product is "Back to meetings".
  • Loading does not change the label; status text goes in the inline status, toast or summary that follows.
