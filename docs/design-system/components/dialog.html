Dialog

A focused decision on top of the page: delete a meeting, or leave the editor with unsaved changes. It holds focus until it is answered or cancelled, and becomes a bottom sheet on phones.

Overview

Use a dialog for a short decision that belongs to the page underneath and must be answered before going on. The Debate App has two, both confirmations:

  • Delete meeting: a destructive confirmation with a danger icon and a danger button. Opens from the delete button on a meeting row. Deletion is soft, but the dialog says "There's no undo" because the UI offers none.
  • Discard changes ("Leave without saving?"): opens from Back, a nav link or browser back while the meeting form is dirty. No icon; "Keep editing" is the primary.

Neither dialog contains a form; the meeting form lives on its own page (see Form layout). Do not use a dialog for messages (use a toast or alert) or for navigation. The account menu is a menu, not a dialog.

Anatomy

  1. Backdrop and frame.backdrop dims the page with --color-bg-backdrop at --z-overlay; .dialog (role="dialog", aria-modal="true") centres the panel at --z-modal.
  2. Icon (destructive only).dialog__icon--danger: 40px circle, danger tint.
  3. Title and descriptionh2.dialog__title, the dialog's name via aria-labelledby, then a muted one-line description via aria-describedby. --text-h4 on phones, --text-h3 from 640px.
  4. CloseGhost icon button, aria-label="Close".
  5. Footer.dialog__footer: sticky, right-aligned. Both dialogs have no body; the header carries the message.

Variants

In-page examples use .dialog--static, a documentation hook that renders the dialog in flow. They carry role="dialog" but not aria-modal, so this page stays readable; the product sets both.

Confirmation: discard changes

Leave without saving?

Your changes to “Universal basic income” will be lost.

Focus starts on "Keep editing", the primary. Escape also keeps editing. Discard is the danger button but sits first (see Do and don't).

Sizes

One panel width, up to 32rem; height grows with content up to the viewport minus --space-12, then the body scrolls and the footer stays.

States

Three states of Delete meeting: default (above), busy and failed. Discard changes has only its default state; it is answered instantly.

  • Default: focus on the safe button (Cancel, Keep editing).
  • Busy: Cancel is disabled; the danger button reads "Deleting…" and carries aria-busy="true". The dialog closes itself on success and the row leaves the list.
  • Failed: a danger alert with role="alert" in the body, "Delete meeting" becomes "Try again", and Cancel regains focus. The page behind is unchanged.
  • No dialog has an invalid state: neither contains a field.

Responsive behaviour

  • Below 640px (--layout-breakpoint-sm) the panel is a bottom sheet: full width, pinned to the bottom, top corners --radius-xl, sliding up over --duration-slow.
  • From 640px it is centred with --space-6 around it, all corners --radius-lg, scaling in; the title grows to --text-h3.
  • The footer is sticky, so the actions stay in reach. Buttons wrap.

Leave without saving?

Bottom sheet at 360px: rounded top corners only, full width. Real pages get this from the base styles, no modifier needed.

Theming

The panel is --color-bg-surface-raised with --shadow-4, over --color-bg-backdrop. In the dark theme the raised surface is lighter than the page, so the panel still lifts off a dark backdrop; the backdrop itself gets darker. The danger icon reads --color-danger-bg and --color-danger-icon.

Accessibility

Role and pattern

The WAI-ARIA APG Dialog (Modal) pattern: role="dialog", aria-modal="true", aria-labelledby pointing at the title and aria-describedby at the description. The page behind is inert while it is open.

Keyboard

KeyAction
Tab / Shift+TabMoves through the controls inside and wraps from the last to the first; focus never leaves the dialog.
EscCancels and closes (Cancel, or Keep editing). Ignored while busy.
Enter, SpaceActivates the focused button.

Focus

On open, focus goes to the safe button ("Cancel", "Keep editing") so a stray Enter is harmless. On close, focus returns to the control that opened it (the row's delete button, or the control that tried to leave). On failed, the alert is announced and focus returns to Cancel.

Labelling

The title names the dialog and the subject: "Delete “Universal basic income”?". The close button is aria-label="Close". The danger icon is aria-hidden; the title and the danger button's words carry the warning.

Motion

The backdrop fades in over --duration-base; the sheet slides up (phones) or the panel scales in from 96% (wider) over --duration-slow with --ease-enter. Reduced motion zeroes both, so it simply appears.

Touch

Footer buttons are 44px tall with 12px between them; the close button is 44px square. The sheet keeps the actions at the bottom, in thumb reach.

Content

  • Titles are a question naming the subject: "Delete “Universal basic income”?", "Leave without saving?".
  • Buttons are specific verbs and the safe one is a real choice: "Cancel" / "Delete meeting", "Keep editing" / "Discard". Never "OK" or "Yes".
  • The description says what happens and that it is final: "It disappears from the list for everyone. There's no undo." and "Your changes to “Universal basic income” will be lost."
  • Failure messages say what did not happen and what to do: "We couldn't delete it. Check your connection and try again."
