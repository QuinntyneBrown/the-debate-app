Rich-text editor

Writes a meeting's Abstract, Agenda and Minutes with six formatting controls.

Overview

The rich-text editor is where organisers write a meeting's Abstract, Agenda and Minutes (L2-024). It is a toolbar of six formatting controls above an editable region, and replaces the Quill snow editor. Its output is HTML, shown later by prose.

  • The six controls: header levels 1 and 2, bold, italic, underline, image and code block.
  • Use it in a tab strip panel, one editor per section. For short single-line values use a text field.

Anatomy

  1. Toolbarrole="toolbar" with an aria-label, on --color-bg-surface-sunken; wraps on narrow widths.
  2. Control.editor__btn, a 36px toggle button with aria-label and aria-pressed.
  3. SeparatorHairline between header, text and insert groups; aria-hidden.
  4. Contentrole="textbox" aria-multiline="true" with an accessible name, styled by prose, with a placeholder when empty.
  5. FrameHairline border and --radius-md; takes the focus ring and the invalid colour.

Variants

One variant, with three modifiers that describe the state of the form rather than a style: .editor--readonly, .editor--busy and aria-invalid="true".

Order of play

  1. Welcome and house rules
  2. Proposition
  3. Opposition
The Agenda editor with Heading 2 active at the caret.

Sizes

One size. Controls are --control-height-sm (36px) square; the content region is at least 14rem tall and then grows with the text. Content padding is --space-4 by --space-5.

States

Real pages get hover and focus from :hover and :focus-within; they are forced with data-state for review. Invalid, read-only, busy and pressed use real attributes and classes.

  • Busy dims the editor to 60% and ignores the pointer while the meeting saves; the page sets the content read-only at the same time.
  • Loading while the meeting is fetched uses a skeleton in place of the editor.

Responsive behaviour

  • The toolbar wraps onto a second row when the six controls and separators do not fit; each control stays 36px.
  • The content region keeps its 14rem minimum and the editor fills the form column at every width.
  • Inside a tab strip only one editor is on screen, so a phone shows one field rather than three.

Theming

The editor reads --color-bg-surface for content, --color-bg-surface-sunken for the toolbar and read-only content, --color-border-default for the frame, --color-accent-subtle and --color-fg-accent for pressed controls and --color-danger-solid for the invalid frame. The component token --field-border carries the frame colour, so hover, focus and invalid only reassign it. Dark-theme values swap automatically.

Accessibility

Role and pattern

The toolbar follows the WAI-ARIA Toolbar pattern: role="toolbar" with an aria-label ("Minutes formatting") holding toggle buttons with aria-pressed. The editable region is role="textbox" with aria-multiline="true" and an accessible name, plus aria-readonly="true" when read-only. Invalid sets aria-invalid="true" on the editor and points aria-describedby at the error text.

Keyboard

KeyAction
TabMoves into the toolbar, then into the text region.
← / →Moves between toolbar controls (roving tabindex).
Home / EndFirst or last toolbar control.
Enter, SpaceToggles the focused control.
Ctrl+B / I / UBold, italic and underline in the text region.
Ctrl+SSaves the meeting.

The text region never traps Tab; it always leaves to the next control.

Focus

The whole editor takes the shared ring (--focus-ring-width of --color-focus-ring) on :focus-within; controls use an inset ring on :focus-visible.

Labelling

Every control has an aria-label naming its action ("Heading 1", "Bold", "Insert image", "Code block"); the visible glyph is not the name. The text region is named after its section ("Minutes").

Motion

Border and control colours transition over --duration-fast; reduced motion zeroes it.

Touch

Controls are 36px with --space-1 between them, so each target clears 24px. The text region is large enough to tap anywhere inside.

Content

  • Placeholders say what belongs there: "What the debate is about", "Order of play", "What happened".
  • Error text names the fix: "Add the minutes before you publish." Not "Invalid content".
  • Control names are the action: "Heading 1", "Bold", "Insert image", "Code block".
