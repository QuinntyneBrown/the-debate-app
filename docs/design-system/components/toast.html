Toast

A small dark card that rises from the bottom of the screen to confirm something just happened ("Meeting saved") or that something needs attention, then gets out of the way.

WCAG 2.2 AAStatus: stablerole="status" / role="alert"

Overview

Use a toast for news about an action that just finished or an event that just arrived, when the person can carry on without reading it. Use an alert or banner when the message must stay on the page, and a dialog when they must decide before going on.

  • Info: something happened that the person did not just do ("Signed in as Jordan Reyes", "Your session lasts 2 hours").
  • Success: their action worked ("Meeting saved", "Meeting created"). Carries at most one next step such as Open. There is no Undo: the API has no restore, so delete confirms in a dialog first.
  • Warning: it has not worked yet ("Not saved yet": you are offline, so the save waits).
  • Danger: it failed and nothing was lost ("We couldn’t save the meeting"), with Try again.

Anatomy

  1. Status icon20px, coloured by --color-*-icon-on-inverse, aria-hidden.
  2. Title.toast__title: what happened, in a few words.
  3. Text (optional).toast__text: what it means or what to do.
  4. Action (optional).toast__action: one underlined button, such as Open or Try again.
  5. Dismiss.close, 24px target, aria-label="Dismiss".
  6. Timer bar.toast__progress: shrinks over 8 s; only on toasts that dismiss themselves.

Variants

All toasts share the inverse surface; the variant only changes the icon and its colour, plus the timing rules below.

Both themes

The toast inverts the page: near-black in the light theme, near-white in the dark theme. The status icons use their own on-inverse tokens so they stay visible on both.

  • Stacked: the newest toast enters at the bottom and older ones slide up; more than three collapse into a "+1 more" line.
  • Paused: hovering or focusing inside a toast stops its timer and the bar; leaving starts it again.

Responsive behaviour

  • Below 640px the region spans the screen with 16px on each side and sits 16px above the bottom.
  • From 640px the region is 24rem wide, 24px from the bottom-right corner.
  • Text wraps; the toast grows taller rather than truncating.
  • Toasts never cover the focused element; the region ignores pointer events except on the toasts themselves.

Theming

The toast reads --color-bg-inverse and --color-fg-inverse, which swap between themes, and one component token, --toast-icon, that each variant sets from --color-{info,success,warning,danger}-icon-on-inverse. To re-theme, override --toast-icon or the inverse pair; do not restyle .toast.

.toast--success { --toast-icon: var(--color-success-icon-on-inverse); }

Accessibility

Role and pattern

The region is a persistent live region, <div class="toast-region" role="status" aria-live="polite">, present in the page from load so that toasts added to it are announced. A danger toast adds role="alert" so the failure is announced at once. Follows the WAI-ARIA status and alert roles; it is not a dialog and never traps focus.

Keyboard

KeyAction
TabReaches the action, then Dismiss, in DOM order after the page content. Focus inside pauses the timer.
Enter, SpaceRuns the action (Open, Try again) or dismisses.
EscDismisses the toast that holds focus.

Focus

Toasts never take focus when they appear. If the focused toast is dismissed or times out, focus returns to the element that triggered it (the Save button, say) or to main.

Labelling

The icon is aria-hidden; the title says the status in words. The dismiss button is named "Dismiss". The timer bar is aria-hidden. Action labels make sense alone: "Try again", not "Go".

.toast__text is drawn at 90% opacity; it stays above 4.5:1 because the inverse pair starts far higher.

Motion

Enters with slide-up over --duration-base; leaves with fade-out (data-state="leaving"). Reduced motion zeroes both, so toasts appear and disappear in place. The timer still runs; time limits are not motion.

Touch

Dismiss is a 24px target with 12px to the action; the action has 4px vertical padding on top of the label line. Nothing relies on hover; tapping the toast body does nothing.

Content

  • Title first, in a few words, past tense for something done: "Meeting saved", "Meeting created", "Signed in as Jordan Reyes".
  • Text says what it means next: the meeting name and time: "Universal basic income · 4:12 pm".
  • Errors say nothing was lost and what to do: "Your changes are still in the form."
  • One action at most, a verb: Open or Try again.
  • Match the variant to the news: "Back online" is good news, so it is success, not warning.

Drift found in the mocks: the with-action mock uses <a class="toast__action"> where the others use <button>, and the stacked mock stamps "Four-day work week · 4:10 pm" while the success mock stamps "4:12 pm" for a different meeting, so the two disagree about what time it is when the story says 4:12 pm. Fixed earlier in the kit: status icons on the dark toast were at 1.4–1.8:1; they now use --color-*-icon-on-inverse (at least 3:1 in both themes), and the 2px timer bar uses --border-width-thick.
