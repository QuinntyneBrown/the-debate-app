Layout primitives

A small set of classes that place everything else: the page container, vertical stacks, wrapping rows, the page header and the centred sign-in card.

WCAG 2.2 AAStatus: stableCSS only, no ARIA

Overview

Compose pages from these primitives instead of writing layout CSS. They read the layout tokens (--layout-container-max, --layout-margin), which change at 768px and 1024px, so pages respond without their own media queries.

  • .container: the page width (max 1280px) and side margins. main on every signed-in page.
  • .stack: children in a column, 16px apart. Forms, sections, dialog bodies.
  • .cluster: children in a wrapping row, 12px apart, vertically centred. Button rows and the page header's action.
  • .page-header (title, subtitle, action).
  • .auth-layout + .auth-card: the centred card on Sign in and Home. The logo mark sits above the card.

Anatomy

The Meetings page, the page that uses the most primitives at once.

  1. Containermain.container: max --layout-container-max, side padding --layout-margin.
  2. Page header.page-header: title block on the left, action on the right, wraps on phones.
  3. Cluster.cluster: the page's one primary action.
  4. Stack.stack: sections one under another, --space-4 apart.

Sizes

Primitives have no size modifiers; gaps and widths come from the spacing and layout tokens listed below.

States

Layout primitives are not interactive and have no states; the only change is responsive (see below).

Responsive behaviour

WidthMarginNotes
Base (phones)--space-4 (16px)Page header action drops under the title.
768px (--layout-breakpoint-md)--space-8 (32px)Same single column.
1024px (--layout-breakpoint-lg)--space-12 (48px)Container stops growing at 1280px.
  • Mobile first: base styles target 360px and only min-width queries add space. There is no desktop-first patch to undo.
  • Every Debate App page is one column. The 12-column grid tokens exist, but no page uses a multi-column grid yet.
  • .page-header wraps: on phones the action drops under the title. .cluster wraps its children; nothing scrolls sideways at 320px.
  • Dialogs become bottom sheets under 640px; see dialog.

Theming

Primitives draw no colour; layout tokens change by breakpoint, not by theme.

Accessibility

Role and pattern

No roles of their own. Put them on the right native element: .container on <main id="main">, .sticky-aside on <aside> or a <section aria-labelledby>, .auth-layout on <main>.

Keyboard

KeyAction
Tab / Shift+TabFollows DOM order. Primitives add no tab stops; never reorder columns visually with order or grid-row, so focus order matches reading order (main before aside).

Focus

html has scroll-padding-top equal to the top bar plus --space-4, so focused content, such as the field an error-summary link jumps to, is never hidden under the sticky top bar.

Labelling

The page header holds the page's only <h1>. Sections and asides are named by their visible heading through aria-labelledby.

Contrast

Primitives draw no colour. Text in .page-header .subtitle uses --color-fg-muted:

Subtitle on canvas
Page title on canvas

Motion

None. html uses smooth scrolling for in-page links, turned off under prefers-reduced-motion.

Touch

.cluster puts 12px between neighbours, above the spacing needed for 24px targets. Content reflows at 320px CSS width (WCAG 1.4.10).

Content

  • Page header: the title says where you are ("Meetings", "Edit meeting"); the subtitle says what is next ("2 upcoming · next is tomorrow at 7:00 pm").
  • One action in the page header at most; it is the page's main action ("New meeting").

Drift still in the mocks:

  • Sixteen back links set style="margin-top: var(--space-4);" on a ghost button directly inside main.container, and eleven meeting forms set style="gap: var(--space-6);" on .stack. Both are spacing decisions that belong in a class (a page-level back-link slot and a .stack--loose modifier).
  • Sign-in, home and the logo tile set the logo's tint inline (background: var(--color-accent-subtle); color: var(--color-fg-accent)) seven times; the home page also sets text-align inline on .auth-card. They are token-based, but they are copy-pasted styling.

The column .grid, .grid--auto, .span-*, .sticky-aside, .cluster--between, .section and .hero__title still exist in ui.css but no Debate App mock uses them, so they are not documented here.
