Component · Identity

Avatar

A circle that stands for a person: their initial on a colour. In the Debate App it is the signed-in admin, Jordan Reyes, as "J" in sky, in the top bar of every page. It is also the button that opens the account menu.

Overview

Use an avatar to show who is signed in. The Debate App has one signed-in person at a time, so the avatar appears once per page, at the right end of the top bar, and opens the account menu (name, username and Sign out). Members such as Priya Nair, Samir Haddad, Lena Fischer and Tom Okafor appear in agendas and minutes as text only; they have no avatar.

  • Button (button.avatar): the top-bar trigger for the account menu. This is the only form the mocks use.
  • Static (span.avatar): decoration next to a name, if a later screen lists people. Not used yet.
  • The colour is Jordan's sky, fixed for the admin; there is no colour picker.
  • There are no photos: the app has no profile photo upload, so .avatar__img is not used.

Do not use an avatar for status; use an alert or toast.

Anatomy

  1. InitialOne capital in --text-label, dark --color-fg-on-cover on a person colour.
  2. Circle--radius-full, sized by --avatar-size (32, 40 or 56px), filled with the person's colour.

Variants

The colour is the person. Jordan is always sky. The plain avatar (accent tint) is the fallback before a colour is set. The stylesheet also defines rose, sun, mint, lilac, sage and peach for future people; no mock uses them yet.

Button avatar

The top-bar trigger, as in every page mock. button.avatar resets the border and adds a hover ring; no inline style needed.
HTML
<button class="avatar avatar--sm avatar--sky" type="button"
        aria-label="Account menu for Jordan Reyes" aria-haspopup="menu" aria-expanded="false">J</button>

Sizes

Small sits in the 64px top bar and is the only size the mocks use. Medium is the default; large is for a future profile or sign-in header.

  • Hover draws a 2px ring in --color-border-strong around the circle.
  • Focus uses the shared focus ring, outside the hover ring.
  • There is no disabled, loading or broken avatar: the account menu is always available and there are no photos to load.

Responsive behaviour

  • Sizes do not change with the viewport. The top-bar avatar is 32px at every width.
  • The avatar never shrinks inside a flex row (flex: none), so a long meeting name wraps around it instead.

Theming

Person colours reuse the pastel --color-cover-* tokens, here --color-cover-sky, with dark --color-fg-on-cover initials in either theme, so Jordan's avatar looks the same in light and dark. The plain fallback uses --color-accent-subtle with --color-fg-accent and does follow the theme. A new person colour is a new .avatar--{colour} modifier that sets the same two properties.

Accessibility

Role and pattern

The account trigger is a native <button> following the APG menu button pattern: aria-haspopup="menu" and aria-expanded. A static avatar is a <span aria-hidden="true"> next to the visible name.

Keyboard

KeyAction
TabFocuses the button avatar (last item in the top bar).
Enter / Space / ↓Opens the account menu and moves focus to its first item.
EscCloses the menu and returns focus to the avatar.

Focus

The shared 2px ring with a 2px offset on :focus-visible. When the menu closes, focus comes back here.

Labelling

An initial is not a name a screen reader can use. The button carries aria-label="Account menu for Jordan Reyes"; a static avatar is hidden because the name is printed beside it.

Motion

None. The hover ring appears instantly.

Touch

The 32px top-bar button clears the 24px minimum and has 16px of space on each side in the top bar. Use medium or larger wherever the avatar is the only target on a phone.

Content

  • Initial: the first letter of the display name ("J" for Jordan Reyes).
  • One letter, capital.
  • The button's label says what it opens and for whom: "Account menu for Jordan Reyes".
  • The menu it opens shows the full name and the username ("Jordan Reyes", "@admin") above Sign out.
