Save bar

Tells the organiser whether the meeting is saved, saving or still to create, and offers Save with its keyboard shortcut.

WCAG 2.2 AAStatus: stableNative <button type="submit">Live region

Overview

The save bar is one flex row in the header of the Edit meeting and New meeting pages, beside the title. It is not a toolbar and not sticky: it holds the status, the shortcut hint and the single primary button of the page. For the button itself see button; for the form it submits see form layout.

  • Status (.inline-status, role="status") says "Saved 3:40 pm", "Saved just now" or "Saving…". Hidden on a new meeting until the first save.
  • Shortcut hint shows Ctrl+S in kbd styling; the shortcut saves from anywhere in the form.
  • Save is the primary button, tied to the form with form="meeting-form" because it lives outside the <form>.

Anatomy

  1. Status.inline-status with a role="status" live region, 16px check icon, --text-body-sm in --color-fg-muted.
  2. Shortcut hintkbd keys: --text-caption, hairline border, --radius-sm.
  3. Save button.btn.btn--primary, type="submit", form="meeting-form".

Variants

Two variants, set by the page: Edit shows status and Save; Create shows only the named action until the first save.

Sizes

The save bar has one size; the button inside is the medium primary and the status and hint are body-small text.

States

The button takes the usual button states; data-state forces hover, focus and active in this static page. The status text changes with the save outcome and is announced because it is a live region.

  • Saving: the button is aria-busy="true" and disabled, its label becomes "Saving…", and the status shows a pulsing dot. Fields become read-only (see form layout).
  • Saved: "Saved just now" in --color-success-fg with a check; it settles to "Saved 3:40 pm" in muted text.
  • Failed or invalid: the status is removed and the error appears in the form summary or an alert; focus moves there, and the button returns to its default state.
  • Disabled is used only while saving.

Responsive behaviour

  • The bar is display: flex; flex-wrap: wrap with --space-3 gaps. Next to the page title it sits at the end; on phones the header stacks and the bar wraps under the title.
  • The shortcut hint is of no use on touch screens; hide it where the device has no keyboard (for example inside @media (hover: none)) and keep the status and Save.
  • At 360px the status and Save share one line; if "Saved just now" and Save do not fit, the status wraps first, never the button label.

Theming

The bar adds no tokens of its own. The status uses --color-fg-muted and, when just saved, --color-success-fg; the hint uses --color-fg-subtle and --color-border-default; the button reads the button component tokens. In dark theme all four swap through the semantic tokens.

Accessibility

Role and pattern

A plain <div> group (no toolbar role: only one control is interactive). The status is a polite live region (role="status") that exists in the DOM before it changes, so "Saving…" and "Saved just now" are announced without moving focus. The button is a native type="submit" associated with the form by form="meeting-form", so Enter in a text field and a click both submit.

Keyboard

KeyAction
Ctrl+S (Cmd+S on Mac)Saves the meeting from anywhere on the page, including inside the rich-text editors. The page prevents the browser save dialog.
TabReaches Save after the page title; the status and hint are not focusable.
Enter, Space on SaveSubmits the form.

Focus

Standard button ring (--focus-ring-width of --color-focus-ring). While saving, the button is disabled and loses focus, so the page moves focus to the result: the status stays a live region, and on error focus goes to the summary.

Labelling

The visible label is the name: "Save" on edit, "Create meeting" on new. The shortcut is also stated in text next to it, so the hint is not the only way to learn it. The busy button keeps its name and sets aria-busy="true".

Motion

The status dot pulses once every --duration-loop while saving and stops under prefers-reduced-motion; the text carries the meaning on its own.

Touch

Save is 44px tall. The bar's gap is --space-3, keeping the status clear of the button.

Content

  • Edit pages say "Save"; new pages say "Create meeting". Never "Submit" or "OK".
  • Status text is short and in the past or present tense: "Saved 3:40 pm", "Saved just now", "Saving…". The time uses lowercase am/pm.
  • The hint names the keys as written on the keyboard: Ctrl+S.
  • Errors are not written in the bar; they go to the form summary or an alert so they can hold detail and a link.
