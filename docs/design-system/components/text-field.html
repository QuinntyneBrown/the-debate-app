Component · Inputs

Text field

A single-line input for the short things the Debate App asks for: a meeting name, a date, a start and end time, a username, a password.

WCAG 2.2 AAStatus: stableNative <input>

Overview

Put .input on a native <input> and wrap it in a form field for its label, help and error. Use the rich-text editor when the answer is formatted text such as an abstract, agenda or minutes.

The mocks use four input types, each with the right keyboard and autofill hints:

  • Text: Name (of the meeting), Username.
  • Date: type="date", the native date picker, for the meeting date. The value is ISO YYYY-MM-DD; the browser shows it in the viewer's locale.
  • Password: autocomplete="current-password" to sign in.
  • Time: type="time", the native time picker, for Start and End. The value is 24-hour HH:MM; the browser shows it in the viewer's locale (7:00 pm or 19:00).

Anatomy

  1. LabelFrom the form field; always visible.
  2. Value--text-body (16px) in --color-fg-default. No placeholder.
  3. Container--field-bg and --field-border, --radius-md, hairline border, --control-height-md tall.

Variants

One look; the type, inputmode and autocomplete attributes do the work. Date and time inputs are native pickers: the browser draws the segmented field and the calendar or clock popup, and the design system only styles the box.

Name, then date, start and end, as in the header strip of Edit meeting. On New meeting the date and time values are empty.
HTML
<input class="input" id="name" name="name" type="text" autocomplete="off" required>
<input class="input" id="date" name="date" type="date">
<input class="input" id="start" name="start" type="time">
<input class="input" id="end" name="end" type="time">

Date and time

Date and time inputs use the same .input box, height and states as text. Their value is machine-readable and locale-independent (2026-10-13, 19:00); the browser formats what the person sees and supplies the picker button. Use min, max or step only when a rule exists; the End time is checked against Start by the form (see form layout), not by the browser.

End must be after the start time (7:00 pm).
Date, time and an invalid end time with its error. The states for every size are in the matrix below.
HTML
<input class="input" id="end" name="end" type="time" value="18:00"
       aria-invalid="true" aria-describedby="end-error">
<div class="field__error" id="end-error">End must be after the start time (7:00 pm).</div>

With trailing button (show/hide password)

Password fields carry an icon-only ghost button inside the box. It toggles the value between dots and plain text so the person can check what they typed. .input-group positions the button; aria-pressed="true" colours the icon.

Sizes

Medium is the default. Large is for the one field a page is about (the Name on New meeting). Small fits a field inside a toolbar or filter.

Small 36px (.input--sm, --font-size-sm), medium 44px, large 52px (.input--lg, --font-size-lg).

Both themes

  • Invalid adds a --color-danger-solid border plus an inset ring, so the edge reads as 2px without shifting layout. Always paired with a .field__error.
  • Read-only is what every field becomes while its form is submitting: the value stays visible, selectable and focusable on a sunken background.
  • Disabled is rarely used: fields stay read-only while a form saves.
  • Invalid date and time: the box turns invalid when a required value is empty or when End is not after Start; the message is in the .field__error.

Responsive behaviour

  • Inputs are width: 100% of their field. Inline max-width caps hint at the expected length: 10 to 12rem for dates and times, 16rem for usernames, 24rem for names in a stacked form.
  • The value is 16px at every width, so no browser zooms the page on focus.
  • Date and time open the platform pickers on phones; the date and time inputs in .meeting-form__header stack one per row under 48rem and sit beside the Name from 48rem up.

Theming

Two component tokens carry every state: --field-bg (default --color-bg-surface, read-only --color-bg-surface-sunken, disabled --color-bg-subtle) and --field-border (default --color-border-strong, hover --color-fg-muted, focus --color-focus-ring, invalid --color-danger-solid). Date and time inputs share both.

/* Each state only reassigns the two tokens */
.input:read-only:not(:disabled) { --field-bg: var(--color-bg-surface-sunken); }
.input[aria-invalid="true"] { --field-border: var(--color-danger-solid); }

Accessibility

Role and pattern

Native <input> with the right type; the browser provides the textbox, spinbutton or date field role. Labelled by a <label for> in a form field.

Keyboard

KeyAction
Tab / Shift+TabMoves focus into and out of the field. Read-only fields stay in the tab order; disabled ones leave it.
← / → in a date or time fieldMoves between the day, month, year, hour, minute and am/pm segments.
↑ / ↓ in a date or time segmentSteps that segment; typing digits sets it. The picker button opens the calendar or clock popup in most browsers.
Tab to the trailing buttonFocuses the show/hide button, right after the input.
Space / Enter on the trailing buttonToggles the password between hidden and shown. Does not submit.
Enter in the inputSubmits the form.

Trailing button

The show/hide button is a native <button type="button">, so pressing it never submits the form. Its aria-label stays "Show password" and aria-pressed toggles between false and true; the script swaps the input type between password and text. Focus stays on the button after the toggle.

Focus

The border turns --color-focus-ring and the shared ring is drawn with no offset, hugging the box. Focus moves to the first field on auth pages and dialogs (autofocus), and to the error summary after a failed submit.

Labelling

Every input has a visible label. Use autocomplete for the signed-in person's own details so password managers and autofill work (WCAG 1.3.5, 3.3.8): username (with autocapitalize="none" and spellcheck="false"), email, current-password, new-password. Names of other people (a reader's name) get no autocomplete.

Disabled text is exempt from contrast minimums; it is only used while a form saves.

Motion

Border colour and ring transition over --duration-fast; zeroed under reduced motion.

Touch

Medium inputs are 44px tall and large are 52px. The small variant is 36px and clears the 24px minimum; keep it out of touch-first forms. Native pickers give large touch targets in their popups.

Content

  • No placeholders. A hint belongs in .field__help, where it stays visible.
  • Pre-fill what is known: Edit meeting opens with the name, date, start and end; New meeting starts empty with focus in Name.
  • Label the three time fields "Date", "Start" and "End". Do not put the format in the label; the browser shows it in the viewer's locale.
  • Keep what was typed after an error; only the person changes it.
  • Mask passwords with the browser's own masking; do not echo them anywhere else on the page.
