Empty state

What a page shows when there is nothing to list yet, or when its data could not load: a round icon, a short title, one sentence, and the one thing to do next.

WCAG 2.2 AAStatus: stableComposition

Overview

Use an empty state in place of a list or a page body that has no content: the Meetings page before the first meeting exists, a meeting that failed to open, a session that has ended. It always offers a way forward.

  • Empty (.empty): nothing here yet, and that is fine. Accent icon. Used by Meetings when no meeting exists.
  • Error (.empty.empty--error): this part of the page didn't load. Danger icon and Try again.
  • Whole-page problems (page not found, offline, sign in to continue, server error) use the same classes at page scale, with an <h1> and extra top padding; see error page.
  • For a failed action, not a failed load, use an alert or a toast.

Anatomy

  1. Icon.empty__icon: 64px circle, accent-subtle (danger-bg for errors), 32px line icon, aria-hidden.
  2. Title.empty__title: an <h2> in the h3 style (an <h1> at page scale); says what is (not) here.
  3. Text.empty__text: one sentence, muted, 36ch max.
  4. Actions.empty__actions: one primary action, optionally one secondary.

Sizes

One size inside a page. The page-scale version, with the page heading and extra top padding, is the error page.

States

The block itself is static; its buttons and links carry the interactive states (see button). What changes is which variant shows and which actions it offers.

  • No mock shows a retrying state: Try again does not change while the request runs. When built, it should become a loading button (aria-busy="true"); on success the real content replaces the whole block.
  • Examples here use <h3> because this page already has its headings; in the product the title is an <h2> under the page's <h1>.

Responsive behaviour

  • Centred at every width, with 48px top and bottom and 24px sides.
  • Text stops at 36 characters wide so it never runs the width of a desktop.
  • Two actions sit side by side and wrap, centred, when they don't fit ("Try again" and "Back to meetings").

Theming

The empty icon reads --color-accent-subtle with --color-fg-accent; the error icon --color-danger-bg with --color-danger-fg. Title and text read --color-fg-default and --color-fg-muted on the page canvas. All are theme tokens; nothing in the component changes between themes.

Accessibility

Role and pattern

Plain content: a heading, a paragraph and native buttons or links. No ARIA role. When it replaces content after a failed load, the page's live region (or the alert role on the retry result) announces the change; the block itself is not a live region.

Keyboard

KeyAction
TabMoves to the primary action, then the secondary.
Enter (and Space on buttons)Runs the action.

Focus

Focus does not jump to the empty state. After Try again fails, focus stays on the button.

Labelling

The icon is decorative. The title is a real heading, so it shows in the heading list. Retry is a <button> (it is an action); "Back to meetings" is a link (it goes somewhere).

Content

  • Title says what is here, not what is missing in the abstract: "No meetings yet", "We can't find that page".
  • Text says why it is fine, or what to check: "Create the first one and the club has a place to meet.", "Check your connection and try again."
  • The action is the next step, in the reader's words: "New meeting", "Try again", "Back to meetings", "Sign in".
  • Errors never blame the reader and never show codes in a section; "Something went wrong on our side" belongs on the server error page.

Drift recorded:

  • Inline page padding: the four page-scale mocks set style="padding-top: var(--space-16);" on .empty.
  • Icon element: the mocks use <span class="empty__icon">; this page uses a <div>. Both render the same.
  • Icon colour: offline uses the accent icon, server-error the danger icon, for the same Try again recovery.
  • Hard-coded name: server-error says "tell Jordan"; the copy should name a role or a link, not a person.
  • Duplicate copy: meeting/error and meeting-edit/error are word for word the same, including "We couldn't open this meeting", even on the edit page.
