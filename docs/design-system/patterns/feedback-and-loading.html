Feedback and loading

Content that is on its way shows as a skeleton in its final shape; an action that is on its way shows on the button that started it.

WCAG 2.2 AAStatus: stablePattern

Overview

Say what happened, where it happened, in the smallest way that is still noticed. Content that is on its way shows as a skeleton in its final shape; an action that is on its way shows on the button that started it; the result of a save shows next to the Save button.

  • Loading content: skeleton rows or blocks with the same layout as the final content, aria-busy="true" on the container.
  • Running an action: the button shows a busy state and its label becomes "Saving…", "Deleting…" or "Signing in…". The rest of the form stays put.
  • Result of a save: an inline status beside the Save button ("Saved just now", "Unsaved changes").
  • Bigger news: a toast or banner; see Notifications.

Responsive

  • Skeletons use percentage widths so they fit any viewport.
  • The save status wraps under the title on phones and stays beside the Save button on wider screens.

Accessibility

  • Busy containers set aria-busy="true"; skeleton children are aria-hidden.
  • The save status is a role="status" live region so "Saved just now" is announced without moving focus.
  • A busy button keeps its place, size and focus, and does not remove itself from the tab order.
  • No time limit is imposed; a slow request keeps showing its busy state.
  • Under reduced motion the shimmer and pulse stop and the skeleton is a static block (2.3.3).

Content

  • Busy labels end with an ellipsis and use the present participle: "Saving…", "Deleting…", "Signing in…".
  • Results are short and past tense: "Saved just now".
  • Do not show a spinner and a skeleton for the same content.
