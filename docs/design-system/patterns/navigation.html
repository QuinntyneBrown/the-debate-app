Pattern · Navigation

Navigation and page structure

One top bar carries the whole app: brand, Meetings, New meeting and the account menu. Pages below the list have a Back button, and a meeting's sections live in a tab strip.

Overview

Everyone sees the same shell: a top bar with the brand, two primary links (Meetings, New meeting), a spacer and the account avatar. Below it each page has one h1. Pages below the list have a Back link to Meetings; within a meeting, a tab strip switches between abstract, agenda and minutes without leaving the page.

  • One primary navigation, always in the top bar; there is no sidebar, tab bar or breadcrumb.
  • One way back. Edit, create and detail pages have a ghost "Meetings" button above the title.
  • Tabs are for sections of one meeting, not for navigating between pages.

Responsive

  • The top bar keeps brand, links and avatar in a single row at every width; the brand text may shorten on very narrow phones.
  • The tab strip scrolls sideways inside its own container when the tabs do not fit.
  • No navigation is hidden at any breakpoint, so no hamburger menu is needed.

Accessibility

  • A skip link to #main is the first focusable element on every page.
  • The primary navigation is a nav with aria-label="Primary"; the current page link has aria-current="page".
  • The tab strip follows the WAI-ARIA tabs pattern: role="tablist", roving tabindex, Left/Right/Home/End to move, panels with aria-labelledby.
  • The avatar button has an accessible name ("Account menu for Jordan Reyes"), aria-haspopup and aria-expanded.
  • Each page has a unique <title> and a single h1.
  • The Back button says where it goes ("Meetings"), not just "Back".

Content

  • Link names are nouns or short verb phrases: "Meetings", "New meeting", "Sign out".
  • Tab names match the section headings: Abstract, Agenda, Minutes.
  • Page titles match the link that led there: "Meetings", "Edit meeting", "New meeting".
