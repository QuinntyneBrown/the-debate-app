Empty and error states

An empty state is an invitation; an error state is an apology with a way forward. Both keep the page around them, say one thing, and offer one main action.

Overview

An empty state is an invitation; an error state is an apology with a way forward. Both keep the page around them (top bar, page title), say one thing, and offer one main action. The Debate App has one empty state (no meetings yet) and five error states, each with its own mock.

  • Empty: nothing has been created yet. Say what will appear here and offer to create it.
  • Error with context: something failed but the shell is fine (meetings could not load, not found, offline, server error).
  • Forbidden: the person is not signed in or the session ended. The page is replaced by a short explanation and a Sign in button.

Structure

Icon, title, one or two sentences, and at most two actions, centred in the content area. Pages that stand alone (not found, offline, server error, forbidden) use an h1 for the title; blocks inside a page use an h2.

Responsive

  • The block is centred with generous top padding on wide screens and shrinks to 16px side margins at 360px.
  • Two actions sit side by side when they fit and wrap otherwise; the primary stays first.

Accessibility

  • Standalone error pages have an h1 and keep the skip link and top bar.
  • The icon is decorative (aria-hidden); the title and text carry the message.
  • Load errors that appear after a request use role="alert" or move focus to the title so they are announced.
  • Try again is a button that re-runs the request; focus stays on it while retrying and the busy state is announced.
  • Colour is never the only signal: the icon, title and words all say what happened.

Content

  • Title says what is true: "No meetings yet", "We couldn't load the meetings", "We can't find that page".
  • Text says why, or what to do, in one or two sentences. Never blame the person.
  • The action names what happens: "New meeting", "Try again", "Back to meetings", "Sign in".
  • Server errors tell the person who to contact and nothing was lost.
