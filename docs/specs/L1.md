# L1 - High-Level Requirements

These requirements are reverse engineered strictly from the implementation in `TheDebateApp` (ASP.NET Web API 2 backend) and `TheDebateApp.Web` (Custom Elements v1 frontend). Nothing is included that the code does not do. Stubs and unreachable code are listed under "Not Implemented" at the end so they are not mistaken for requirements.

## L1-001: Meeting Management (API)
The system must let callers create, update, list, retrieve, and soft-delete meetings. A meeting has a name, date, start, end, abstract, agenda, and minutes.

## L1-002: Article Management (API)
The system must let callers create, update, list, retrieve, and soft-delete articles. Only the article title is exposed through the API.

## L1-003: Architecture and Architecture Item Management (API)
The system must let callers create, update, list, retrieve, and soft-delete architectures and architecture items. Only the name is exposed through the API.

## L1-004: User Management (API)
The system must let callers create, update, list, retrieve, and soft-delete users, and must let a caller retrieve the currently authenticated user.

## L1-005: Digital Asset Management (API)
The system must store uploaded files in the database, serve them back by unique id or by name with their original content type, and let callers create, update, list, retrieve, and soft-delete digital asset records.

## L1-006: Authentication and Authorization
The system must issue JSON Web Tokens (JWT) through an OAuth2 resource-owner-password token endpoint, validate bearer tokens on protected endpoints, and carry user roles as claims in the token.

## L1-007: Soft Deletion
The system must never physically delete records through the API. Removal marks a record as deleted, and deleted records must be excluded from all reads and from update matching.

## L1-008: API Conventions
The system must expose attribute-routed endpoints under `api/{resource}/{action}`, serialize responses as indented camelCase JSON only, allow cross-origin requests from any origin, and publish a Swagger description of the API.

## L1-009: Database Seeding
The system must seed an administrative user and an introductory meeting when migrations run.

## L1-010: Client Routing and Navigation
The web client must be a single-page application with client-side routes for the home page, login page, meeting list, meeting creation, and meeting editing, and must keep the browser history and the active navigation link in sync with the current route.

## L1-011: Meeting Management (Web Client)
The web client must let a user list meetings, open a meeting for editing, create a meeting, save a meeting, and delete a meeting, using rich-text editors for the abstract, agenda, and minutes and date/time pickers for the date, start, and end.

## L1-012: Client Session Storage
The web client must persist named key/value items to browser local storage under a single application key and must attach a stored bearer token to authenticated user requests.

## L1-013: Reusable Web Components
The web client must provide reusable custom elements for a link, a header, a tab strip, a file drop zone, and a rich-text editor wrapper.

## Not Implemented (observed stubs, excluded from requirements)
- Registration: `IIdentityService.TryToRegister` throws `NotImplementedException`; the client calls `/api/user/regiser` (sic), which has no route; `ce-registration` renders an empty `div`.
- Login UI: `ce-login` renders two inputs and a button with no event handlers; `UserService.tryToLogin` exists but is never invoked. The route table marks routes with `authRequired`, but the router never reads it.
- Roles and invitation codes: services exist and are registered, but no controller exposes them.
- Articles (client): `ce-articles`, `ce-article`, `ce-article-item` render an empty `div`; `ce-article-edit` is implemented but never routed to. The client article model uses `name` while the API exposes `title`.
- Users (client): `ce-users`, `ce-user`, `ce-user-item` render an empty `div`.
- Models `Comment`, `Like`, `Technology`, `TechnologySnapShot`, `ArticleSnapShot`, `YouTubeVideo` are not in the `DbContext` and have no endpoints.
- `ArticlePlugIn`, `LoginRedirect`, `modal.ts`, `Constants`, `IdentityClient`, `SearchClient` are empty.
- `HandleErrorAttribute.OnException` is empty: exceptions are not logged or transformed.
- Known wiring defect: `UnityConfiguration` registers `IArchitectureService` to itself rather than `ArchitectureService`, so `ArchitectureController` cannot be resolved at runtime.
